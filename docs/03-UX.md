# 03 — UX Specification

## UX goal

The app should remove decisions and minimize taps.

The critical use context is:

- user is in a gym;
- user may be standing;
- user may be sweaty;
- one hand may be occupied;
- attention is limited;
- interactions should be obvious without reading instructions.

---

# Navigation

Bottom navigation:

- Today
- Progress
- Plan

Use a minimal settings/profile control in the top-right where needed.

Avoid hamburger menus.

---

# App launch

If authenticated:

- open directly to Today.

If not authenticated:

- show a minimal sign-in screen;
- email field;
- magic link / OTP;
- no marketing site required.

---

# Today flow

## State A — lifting + cardio day

Show:

1. date;
2. phase/week;
3. primary lifting card;
4. `Start Workout`;
5. later cardio card;
6. small weekly completion.

## State B — Saturday

Show:

1. long aerobic card;
2. mobility checklist card.

## State C — Sunday

Show:

- `Rest · Fast`;
- no training CTA;
- calm recovery state.

---

# Start Workout flow

```text
Today
→ Start Workout
→ Active Exercise
→ Log Set
→ Rest Timer
→ Next Set
→ Complete Exercise
→ Next Exercise
→ Finish Workout
→ Summary
```

---

# Active exercise screen

## Header

- close/back with confirmation only if exiting;
- `1 / 7`;
- Overview button.

## Exercise block

- name;
- visual;
- set × rep target;
- rest target.

## Previous performance

Compact, not dominant.

Example:

```text
Previous
185×6 · 185×5 · 185×5 · 185×4
```

## Current set

Large controls.

Weight:

- numeric field;
- minus;
- plus;
- display unit `lb`.

Reps:

- numeric field or fast chip options near rep range;
- make common target values one-tap.

Example for 4–6 reps:

- 4
- 5
- 6

Manual entry remains possible.

## Complete Set CTA

Primary full-width action.

On tap:

1. save set immediately;
2. optimistic UI update;
3. automatically enter rest state.

---

# Rest state

The timer is prominent.

Display:

- remaining time;
- completed set summary;
- next-set target.

Controls:

- `+30 sec`
- `Skip`

Timer rules:

- timer continues when app backgrounds;
- use timestamp-based timer, not fragile decrement-only state;
- if user returns after timer elapsed, show rest complete;
- subtle haptic-like visual feedback if supported by browser;
- no loud audio by default.

When timer reaches zero:

- transition to `Ready` state;
- next set controls become primary.

---

# Completing an exercise

When all prescribed sets are done:

Show:

- success check;
- brief summary;
- next exercise name and thumbnail;
- `Continue`.

Do not force a celebratory animation longer than ~500–700 ms.

---

# Workout Overview

Accessible throughout.

Use a sheet/drawer or full-screen mobile list.

Each row:

- status icon;
- exercise name;
- completed sets / total sets;
- optional small thumbnail.

Tap a row:

- jump to exercise.

Current exercise visibly highlighted.

Do not lose logged sets when changing order.

---

# Exercise visual behavior

Default state:

- image/animation visible in a contained card.

Tap:

- expands to a larger modal/sheet;
- show optional short cues.

Do not make users navigate away from active workout.

---

# Workout completion

Show only useful information.

Example:

```text
Workout complete

Upper Strength
7 exercises
21 working sets
58 min

Bench Press
185 × 6 / 6 / 5 / 5

Next scheduled
Bike · 20 min easy
```

CTA:

- `Done`

Optional secondary:

- `View Progress`

No social share.

---

# Cardio flow

```text
Today
→ Start Cardio
→ Timer
→ Finish
→ RPE
→ Save
```

During cardio:

- large elapsed / remaining time;
- target duration;
- target effort;
- pause;
- finish.

At finish:

- RPE 1–10;
- save.

Do not require notes.

---

# Mobility flow

Checklist.

Tap row:

- mark complete.

Timed rows may offer:

- `Start 30 sec`.

No separate workout mode needed.

---

# Progress UX

Keep this calm.

Sections:

## Strength

Default select:

- Bench Press.

Chart should show an understandable performance trend.

Possible graph:

- best working-set load at target reps;
- optional estimated 1RM as secondary.

Allow exercise selector for key lifts only.

## Relative Strength

Show:

- pull-up reps trend;
- dip reps trend.

## Cardio

Show:

- weekly aerobic minutes;
- longest session.

## Consistency

Show:

- lifting completed / scheduled;
- cardio completed / scheduled;
- current block completion.

Avoid more than 2–3 charts visible simultaneously.

---

# Plan UX

Top:

- Phase 1 — Foundation;
- Week X of 12;
- progress bar.

Then seven day rows/cards.

Tap day:

- read-only exercise list;
- sets × reps;
- rest;
- cardio if applicable.

No editing.

---

# Settings

V1 only:

- sign out;
- preferred weight unit, default lb;
- optional email display;
- PWA/install help if needed;
- app version.

Do not create a large settings area.

---

# Error states

## Failed cloud save

- keep local optimistic state;
- show small `Syncing…` status;
- retry;
- do not block workout.

## Offline

- workout should remain usable;
- writes may queue locally and sync later where practical;
- clearly show offline state without alarming modal.

## Authentication expired

- preserve unsynced local session if possible;
- ask user to re-authenticate;
- sync after success.

---

# Accessibility / ergonomics

- minimum comfortable tap target ~44px;
- numeric inputs should trigger numeric keyboard;
- avoid tiny text below 13–14px;
- active workout key numbers should be large;
- do not rely on color alone for completed/current states;
- support reduced-motion preferences;
- sufficient contrast on white/off-white surfaces.

---

# Motion rules

Motion communicates:

- completion;
- state transition;
- rest;
- next exercise;
- drawer expansion.

Motion does not decorate.

Preferred durations:

- micro interaction: 120–200 ms;
- layout transition: 180–280 ms;
- success state: <=700 ms.

Use spring motion sparingly.

---

# Empty/loading states

Avoid skeleton overload.

On first load:

- simple branded loading state.

No workout history:

- Progress should say the data will appear after workouts are completed.

No previous exercise performance:

- show `First session` rather than empty dashes.
